# portscan

Go-пакет для проверки доступности TCP-портов методом **TCP Connect**
(обычное установление соединения через стандартный сетевой стек Go).
Пакет встраивается в любое приложение: не зависит от CLI, фреймворков и
внешних сервисов, не использует глобального изменяемого состояния.
Сторонних зависимостей нет — только стандартная библиотека Go 1.25.5.

```bash
go get github.com/Usarotonkachi/portscan
```

Тесты:

```bash
go test -race ./...
```

## Использование

```go
scanner, err := portscan.New(
	portscan.WithConcurrency(100),
	portscan.WithConnectTimeout(500*time.Millisecond),
)
if err != nil {
	return err
}

results, err := scanner.Scan(ctx,
	[]string{"192.168.1.10", "2001:db8::1", "example.com"},
	portscan.Union(portscan.Range(1, 1024), portscan.List(8080, 8443)),
)
if err != nil {
	return err // некорректные цели или порты
}

for r := range results {
	fmt.Printf("%s %s:%d %s\n", r.Host, r.IP, r.Port, r.State)
}
if ctx.Err() != nil {
	// сканирование прервано, часть портов не проверена
}
```

Собрать всё в срез: `slices.Collect(results)`.

## Публичный API

| Сущность | Назначение |
|---|---|
| `New(opts ...Option) (*Scanner, error)` | Создаёт сканер. Ошибки опций оборачивают `ErrInvalidOption`. |
| `WithConcurrency(n)` | Максимум одновременных подключений, `n >= 1`, по умолчанию 100. |
| `WithConnectTimeout(d)` | Таймаут одного подключения, `d > 0`, по умолчанию 1 с. |
| `WithDialer`, `WithResolver` | Свои реализации подключения и DNS (прокси, тесты). Стандартные `*net.Dialer` и `*net.Resolver` подходят как есть. |
| `(*Scanner).Scan(ctx, targets, ports)` | Проверяет входные данные и возвращает `iter.Seq[Result]`. |
| `Ports`, `List`, `Range`, `Union` | Набор портов: отдельные порты, диапазоны и их объединение. |
| `Result`, `State` | Результат проверки одного порта на одном IP. |
| `TargetError`, `ResolveError`, `Err*` | Ошибки; проверяются через `errors.Is` / `errors.As`. |

```go
type Result struct {
	Host     string        // цель в том виде, в котором её передали
	IP       netip.Addr    // проверенный адрес; невалиден, если имя не разрешилось
	Port     uint16
	State    State
	Duration time.Duration // время попытки подключения
	Err      error         // nil только для StateOpen
}
```

| `State` | Когда |
|---|---|
| `StateOpen` | соединение установлено (и сразу закрыто) |
| `StateClosed` | соединение отклонено (`ECONNREFUSED`) |
| `StateTimeout` | истёк таймаут подключения или ядро вернуло `ETIMEDOUT` |
| `StateUnreachable` | `ENETUNREACH`, `EHOSTUNREACH`, `ENETDOWN`, `EHOSTDOWN` |
| `StateCanceled` | проверка прервана отменой контекста |
| `StateError` | всё остальное, в том числе ошибка DNS |

Состояние определяется по типу ошибки (`syscall.Errno`, `context.Canceled`,
`net.Error.Timeout()`), а не по её тексту. Коды ошибок Unix и Windows
разбираются отдельно (`classify_*.go`).

### Почему итератор, а не канал

`Scan` возвращает `iter.Seq[Result]` — читается тем же `for r := range results`,
но не требует от пользователя дочитывать канал до конца:

- `break` или отмена контекста останавливают запуск новых проверок; к моменту
  выхода из цикла запущенные проверки завершены, соединения закрыты,
  горутины остановлены;
- если читать медленно, сканер ждёт: одновременно идёт не больше
  `concurrency` проверок и столько же готовых результатов ждут в буфере,
  память и число горутин ограничены;
- `Scanner` не меняется после создания, его можно использовать из нескольких
  горутин; каждый `range` по итератору — новое сканирование.

Внутри используются каналы; каждый закрывает единственный отправитель после
завершения всех отправок.

## Граничные случаи

Ошибки входных данных возвращаются из `Scan` до начала сканирования, все сразу
(через `errors.Join`).

| Вход | Поведение |
|---|---|
| пустой список целей | `ErrNoTargets` |
| пустой хост `""` | `ErrEmptyTarget` |
| `host:port`, URL, `999.1.1.1`, `10.0.0`, мусор в IPv6 | `ErrInvalidTarget` (в DNS такое не отправляется) |
| IPv6 `::1`, `[2001:db8::1]`, `fe80::1%eth0` | поддерживается |
| повторяющиеся цели | проверяются один раз (регистр имени и форма записи IP не важны) |
| имя с несколькими IP | проверяется каждый адрес, IPv4 и IPv6; `Host` один, `IP` разные |
| неразрешимое имя | для каждого порта `StateError` с `*ResolveError`; остальные цели сканируются |
| порт 0 или > 65535 | `ErrInvalidPort` |
| обратный диапазон `Range(1000, 1)` | `ErrInvalidRange` |
| повторяющиеся порты | проверяются один раз |
| пустой список портов | `ErrNoPorts` |

При отмене контекста прерванные подключения выдаются как `StateCanceled`,
а не начатые проверки не выдаются вовсе — признаком неполного результата
служит `ctx.Err() != nil`.

## Устройство

1. DNS-имена разрешаются параллельно (не более 16 запросов одновременно).
2. Для каждой пары «IP, порт» берётся слот семафора размером `concurrency`
   и запускается горутина. Слот освобождается после передачи результата,
   поэтому проверок одновременно не больше `concurrency`.
3. Проверка — `DialContext` с таймаутом; соединение сразу закрывается
   (`SetLinger(0)`, чтобы не копить сокеты в `TIME_WAIT`).

## Ограничения

- Только TCP Connect: без SYN/UDP, raw sockets, определения ОС и сервисов.
- CIDR не поддерживается.
- `concurrency` ограничен лимитом файловых дескрипторов процесса (`ulimit -n`).
- Порт за брандмауэром, который молча отбрасывает пакеты, будет `StateTimeout`.
- Прозрачный прокси или VPN может принимать соединения на любой адрес — тогда
  порт будет `open`.
